## Riskiest flags (preset on unless noted)

1. `transform_scales_each_tolerance`, `transform_model_size_from_body_box` (WR-507/508, fork #49/#50, preset **fork/on**). **These flags are dead on main.** PR #1539 (commit 5f61026e6, "port: SM_API files and conversion") removed the guarded branches in `topology/brep/p5.rs` `transform_in` that 086138ff3 had added, together with their tests `transform_scales_each_tolerance_wr507` and `transform_sizes_a_body_without_vertices_wr508`. The fields still exist, sit in the preset and are switched on by SolidCraft, but they change nothing. The WR-507/508 records still describe the removed code. This looks like a bad merge or rewrite; restore the code and tests.
2. `corner_blend_coons_patch_tangent_to_sides` (WR-547, fork cae8618, **D**). The only test, `wr_547_notch_corner_patch_is_tangent_to_its_rounds`, sets the flag and passes, but the guard (`nurbs/b_spline_surface_n_lib/p2.rs:2006`, after `create_coons_patch`) is never executed. 3. `fillet_corner_ball_center_from_axes` (WR-541, fork bc6ddf9, **C**). No test sets it, and it is not reached by any SolidCraft case. It also needs `fillet_corner_ball_patch`.
4. `offset_extended_edges_mated` (WR-344, reported, **B**). Two tests reach the guard but neither fails forced off: `issue_1795` asserts that the shell closes "as with the defaults". #1818 shows that this flag alone returns Ok with a non-manifold zero-volume wall on a square-to-circle loft. No test pins the fork-specific behaviour, and the known invalid-body case has no test.
5. `offset_clip_right_side_out` (WR-342, reported, **D**). Its only test is `#[ignore]` ("fixture does not reproduce"), and it fails when run. 7. `fillet_trace_rejects_short_step` (WR-503, reported, **C**). No solidcore test; the regression test lives only in SolidCraft. No SolidCraft fixture reaches it.
8. `uv_trim_joins_drop_pieces` (WR-543, fork e36feb1, **C**). No test sets it. `longest_drop_run_joins_the_pieces_that_meet` tests the helper with the default kernel, so the call-site guard (`topology/edgeuse/p3.rs:769`) is never exercised.
9. `imprint_extends_edge_to_proto_vertex` (WR-453/498, fork a8caccd/ffaf4e8, **B**). Six thread-groove and loft-union tests reach the guard with the flag on, but none fails forced off. Its sibling `imprint_trims_edge_to_proto_vertex` carries all the asserted effect.

## Method

1. Parsed the 158 `UpstreamFixes` fields and their docs from `crates/solidcore/src/kernel.rs`, and the fork/reported/off lists from `kernel/solidcraft.rs`, on origin/main `d1c6fc48a`. Grepped guards (`fixes.<flag>` reads in `crates/solidcore/src`) and setters (tests, src test modules, difftest, `fixtures/solidcraft/*.json`).
2. Instrumentation (uncommitted; `flaghit.patch` next to this file): a script rewrote each of the 238 production reads `fixes.<flag>` into `fixes.hit_<flag>()`. When the flag is on, that call records `(flag, test binary, thread = test name)` to a log. When `FLAGHIT_FORCE_OFF=<flag>`, it also returns `false` for that flag. Built with `cargo test -p solidcore --profile difftest --no-run` (15 min).
3. Ran the full solidcore suite once single-threaded (178 binaries, 3128 passed, 0 failed, 4 min), plus the 9 non-probe `#[ignore]` tests separately (4 of them fail as documented). Hits only count when the flag is on, so every hit comes from a test that turned the flag on.
4. Kill pass: for every flag, re-ran exactly the tests that hit it, with that flag forced off. A failure means a test asserts behaviour that depends on the fork branch.
5. SolidCraft runner (`difftest --solidcraft-cases`, Rust only), per file:
   - with each case's own `fixes`: PASS 137, DEFERRED 21, ERROR 1 (3369/edge_ends_on_seam, 1001);
   - with every flag on (a temporary `FLAGHIT_ALL_ON` hook in `run_rust`): PASS 138, DEFERRED 21. 83 flags were reached.
   
   Force-off reruns covered the fixture-named flags and the B/C/D flags those cases reach. Also ran the difftest lib tests (95 passed).
6. Operation vs helper: a killing test counts as operation-level if its body, or a helper it calls (3 levels in the same file), calls a modelling entry point. I corrected obvious misreads by hand: flag names that match the pattern, primitives used only as fixtures, and mass-property flags where measurement is the operation.

**Limits.**
- A hit means the flag's decision point was evaluated with the flag on. It does not mean the guarded body ran. Where a guard is `if flag && cond`, the inner condition may be false; the kill pass catches that only when a test asserts the difference.
- B-unit vs A comes from reading call sites, not coverage, so some B-unit flags may be reachable end to end without a test showing it.
- Class A says nothing about whether the fork behaviour is correct or valid (cf. #1818), only that a test pins it.
- difftest `--unit` gates were not run with flags on. They run the defaults by design.
- SolidCraft's own test suite (`crates/smlib` in solidcraft) was not run.
